## **Step 3 — Connect your existing LangGraph agent to Opik**

Your `workflow.py` already has:

```
agent_graph = build_graph()
```

We can add tracing without changing your nodes, state, or graph edges.

Add this import near the top of `app/rag/workflow.py`:

```
from opik.integrations.langchain import OpikTracer, track_langgraph
```

Then replace:

```
agent_graph = build_graph()
```

with:

```
agent_graph = build_graph()opik_tracer = OpikTracer(    project_name="it-support-agentic-rag")agent_graph = track_langgraph(    agent_graph,    opik_tracer)
```

Keep your existing `ask()` function unchanged.

Now every call to:

```
result = ask("What is the employee leave policy?")
```

will be traced by Opik.

You can inspect the graph execution and node activity in the Opik dashboard. This is the documented recommended integration for LangGraph.&#x20;

## **Step 4 — Configure basic evaluation metrics**

For your first evaluation, I recommend just two built-in metrics:

**1. Answer Relevance**

Higher is better

Measures whether the generated answer addresses the question.

Score: 0.0 to 1.0

**2. Hallucination**

Lower is better

Checks whether the generated answer contains claims unsupported by the retrieved context.

Score: 0.0 means no hallucination detected; 1.0 means hallucination detected.

These metrics are available directly in `opik.evaluation.metrics`.&#x20;

[image](https://www.google.com/s2/favicons?domain=https://www.comet.com\&sz=32)

Opik Documentation+2



### **Configure Groq as the evaluation judge**

The metrics use an LLM judge. Since you already use Groq, we can try Groq rather than introduce another provider.

Install LiteLLM:

```
pip install -U litellm
```

Add your existing Groq API key under the environment variable LiteLLM expects:

```
GROQ_API_KEY=your_existing_groq_api_key
```

Use a Groq model supported by LiteLLM, for example:

```
JUDGE_MODEL = "groq/llama-3.3-70b-versatile"
```

The Opik metrics accept a LiteLLM-compatible model name.&#x20;

[image](https://www.google.com/s2/favicons?domain=https://www.comet.com\&sz=32)

opik+1



If Groq no longer offers that model to your account, substitute a currently available Groq model. This judge model is separate from the model used by your agent.

## **Step 5 — Create your evaluation runner**

Create:

```
evals/run_opik_evaluation.py
```

Use this code, adapted to your actual `ask()` function and `AgentState`:

```
import osfrom dotenv import load_dotenvimport opikfrom opik.evaluation import evaluatefrom opik.evaluation.metrics import (    AnswerRelevance,    Hallucination,)from app.rag.workflow import askload_dotenv()DATASET_NAME = "novacore_golden_dataset"PROJECT_NAME = os.getenv(    "OPIK_PROJECT_NAME",    "it-support-agentic-rag")# LiteLLM-compatible Groq modelJUDGE_MODEL = "groq/llama-3.3-70b-versatile"def target(dataset_item: dict) -> dict:    """Run one golden question through the existing agent."""    question = dataset_item["question"]    result = ask(question)    # Collect actual retrieved KB documents.    kb_docs = result.get("kb_docs") or []
```

Run it from your project root:

```
python -m evals.run_opik_evaluation
```

The runner follows Opik's current Python evaluation API: `evaluate(dataset=..., task=..., scoring_metrics=...)`.&#x20;

[image](https://www.google.com/s2/favicons?domain=https://www.comet.com\&sz=32)

opik+1



**Important limitations of this first evaluation:**

- `AnswerRelevance` checks relevance, not whether the answer matches your golden reference answer.
- `Hallucination` checks the answer against the supplied context; it is not a complete factual correctness test.
- `reference_answer` is returned by the task for future evaluators, but these two metrics do not use it.
- For direct-answer cases, the context may be empty. Relevance still works because we set `require_context=False`; hallucination then evaluates the answer without retrieved evidence.

Run all 76 examples initially with `task_threads=1`. This avoids running many Groq calls simultaneously.

## **What metrics should you keep for your project?**

I recommend starting with these four. The first two are Opik's built-in LLM metrics; the last two are simple Python checks.

| Metric            | Type         | Desired result                   |
| ----------------- | ------------ | -------------------------------- |
| Answer relevance  | LLM judge    | High                             |
| Hallucination     | LLM judge    | Low                              |
| Answer presence   | Python check | 100%                             |
| Citation presence | Python check | High for KB-answerable questions |

You can add the Python checks after the first evaluation works. Don't complicate the first run.
